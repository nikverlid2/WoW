# Подключение Кламас B2B

Таблица: https://docs.google.com/spreadsheets/d/1XNp-7dekkTVhWCb8fMKIzKOnluDTCZxMgnTMNxM48xU/edit

Код готов к установке. Сейчас публичный сайт использует демо-кабинет; живое подключение включается после публикации Google Apps Script владельцем таблицы. Эта интеграция рассчитана на небольшой пилот, а не на замену 1С.

## Однократная установка

1. Откройте таблицу → **Расширения → Apps Script**.
2. Вставьте содержимое [Code.gs](Code.gs) в файл `Code.gs`.
3. Нажмите **+ → HTML**, назовите файл `Portal`. Вставьте содержимое [Portal.html](Portal.html).
4. Сохраните проект. Вернитесь в таблицу и обновите страницу. В меню **Кламас B2B → Установить** подтвердите разрешения Google для своего скрипта. Скрипт работает только с этой таблицей; почту не отправляет.
5. В редакторе Apps Script: **Развернуть → Новое развёртывание → Веб-приложение**. Выполнять от имени **вас**, доступ **Все**. Это открывает только страницу входа: данные выдаются сервером после проверки личного ключа. Саму Google-таблицу публичной делать не нужно.
6. Скопируйте адрес вида `https://script.google.com/macros/s/…/exec` и передайте его в этот чат. Я подключу кнопку входа на сайте. Можно самостоятельно вставить адрес в `KLAMAS_B2B_URL` файла [b2b-connection.js](../b2b-connection.js).

Если политика вашего Google Workspace запрещает публичные веб-приложения, понадобится разрешённый организацией способ развёртывания. Не меняйте политику аккаунта ради обхода ограничения.

## Обычная работа

- На нужном листе нажмите **Кламас B2B → Новая строка**. ID заполняется автоматически.
- Создайте компанию на листе **Компании**, статус `Активна`.
- Создайте сотрудника на листе **Пользователи**: ID компании, email, имя. Выберите его строку и **Выдать / заменить ключ**. Ключ показывается один раз; передайте его человеку лично. Таблица хранит только хеш. Пароли от Google не нужны.
- Добавьте заказ и позиции. В позиции укажите количество и конечную цену за единицу в рублях. Сумма заказа пересчитается.
- Добавляйте платежи отдельными строками. `Зачислен` увеличивает оплату, `Возврат` уменьшает её. Отрицательные суммы для возвратов не используйте.
- Для частичной поставки создайте несколько отгрузок одного заказа. На листе **Состав отгрузок** укажите ID отгрузки, ID позиции и фактическое количество. Не превышайте заказанное количество.
- В **Документах** укажите ID компании, ID заказа (если есть), название, статус `Доступен` и ссылку Google Drive. Сам файл предоставьте нужному клиенту средствами Google Drive. Скрипт не меняет разрешения документов.
- В кабинете клиент видит данные при входе и по кнопке **Обновить**. Обращения из кабинета автоматически добавляются в таблицу; ответы менеджера в соответствующем столбце видны после обновления.
- Вкладки кабинета: обзор, заказы с составом, отгрузки с этапами, платежи, документы, обращения, реквизиты и контакты компании.

Роль пользователя — информационное поле. Все активные сотрудники одной компании видят одинаковые данные своей компании. Для разных прав бухгалтерии и закупок потребуется отдельная настройка ролей.

## Правила данных

- Не переименовывайте заголовки и не меняйте уже используемые ID.
- Таблицу редактируют только доверенные сотрудники. Клиенты не должны получать к ней доступ.
- Служебные заметки можно добавлять в собственных столбцах справа: сервер передаёт только явно разрешённые поля.
- Поля `Комментарий для клиента` и `Ответ менеджера` видны клиентам.
- Тестовые строки начинаются с `DEMO`. Удалите их перед рабочим использованием; формулы новых строк создаются через меню.
- Формулы, подготовленные в шаблоне, охватывают первые 5000 строк источников. Меню **Новая строка** создаёт формулы с открытыми диапазонами. Для крупных объёмов данных используйте базу данных/учётную систему.

## Доступ и ограничения

Ключи генерируются индивидуально. В таблице хранится SHA-256 с серверным секретом. Сессия действует до часа и может завершиться раньше при очистке Google Cache. Замена ключа или отключение пользователя/компании блокирует старые сессии при следующем запросе. Логины и обращения фиксируются в журнале. После 8 неудачных попыток для одного email вход временно ограничивается.

Код не скачивает всю таблицу в браузер: сервер сначала проверяет сессию и компанию, затем отбирает связанные заказы, позиции, отгрузки и документы. Для больших клиентских баз и повышенных требований к доступу нужен полноценный сервер с управляемой авторизацией.

Перед реальными данными: создайте две тестовые компании и два входа; убедитесь, что каждая видит только свои записи. Затем проверьте отключение пользователя, замену ключа, создание обращения и доступ к документу. Локальные проверки выполнены; проверка в Google после развёртывания ещё требуется.
